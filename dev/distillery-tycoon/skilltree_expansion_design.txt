1. ЭКОНОМИКА ОЧКОВ (вариант D)
================================================================================

Проблема: стоимость узлов плоская (1-2-3-2), всё дерево скупается «подряд»,
кейстоуны не ощущаются как вложения.

Решение — растущая цена внутри ветки. Единая шкала:

    узел 1 = 1 очко
    узел 2 = 2 очка
    узел 3 = 4 очка
    узел 4 (кейстоун/финал) = 6 очков

Правки к текущему файлу:
    d1: cost 1 (было 1)   d2: cost 2 (было 2)   d3: cost 4 (было 3)   d4: cost 6 (было 2)
    r1: cost 1            r2: cost 2            r3: cost 4 (было 3)   r4: cost 6 (было 2)
    c1: cost 1            c2: cost 2            c3: cost 4 (было 3)   c4: cost 6 (было 2)
    f1: cost 1            f2: cost 2            f3: cost 4 (было 2)   f4: cost 6 (было 2)
    h1: cost 1            h2: cost 2            h3: cost 4 (было 2)   h4: cost 6 (было 2)
    o1: cost 1            o2: cost 2            o3: cost 4 (было 3)   o4: cost 6 (было 2)
    a1: cost 1            a2: cost 2            a3: cost 4 (было 3)   a4: cost 6 (было 2)

Итог: вся ветка целиком теперь стоит 13 очков (было 8). Очки ветки не собираются
«мимоходом», игрок выбирает 2-3 ветки, а не все семь. Если очков в игре больше,
чем предполагалось, — компенсируется тем, что новые ветки (раздел 4) забирают
эту избыточную валюту.

Компенсация сложности: кросс-узлы (раздел 3) дают мягкие мосты между ветками,
чтобы «разумный» билд по-прежнему собирался.

2. ВАРИАНТ A: ВЗАИМНЫЕ ЗАВИСИМОСТИ ВЕТОК
================================================================================

Идея: дерево из веера превращается в сетку. Производство требует сырья,
коммерция требует производства.

Правки requires (меняется только массив, узлы те же):

    f2 «Теплица»          requires: ['f1', 'h1']
        Смысл: сидераты из травяной ветки. Теплица без агрономии не работает.
        Игрок, идущий чисто в овощи, вынужден взять 1 узел трав.

    a3 «Рецепт медовухи»  requires: ['a2', 'd1']
        Смысл: мёд надо ещё и перегнать уметь. Связка пасека-дистилляция.
        Золотая жила теперь стоит дольше — честно за её доходность.

    c4 «Сеть таверн»      requires: ['c3', '<любой кейстоун производства>']
        Смысл: продавать нечего — таверны не нужны. Технически поле requires
        умеет только «все из списка», поэтому вводим новое поле:

            requiresAny: ['d3', 'r3', 'o3', 'bk4', 'soc4', 'hnd4']

        В canLearn: узел доступен, если выполнен requires (все) ИЛИ найден
        хотя бы один id из requiresAny. Одна функция на 3 строки.

    o4 «Ягодная аллея»    без изменений (уже требует o3 — норм).
    r4 «96,6 без вопросов» без изменений (уже требует r3 — норм).

Побочный эффект: усиливается драматургия конфликта d3 против r3/o3 —
теперь выбор кейстоуна ещё и блокирует/открывает коммерческую верхушку.

7. НОВЫЕ ПОЛЯ Bonuses И EFFECTS

Bonuses (добавить к существующим):
    meadPrice: number      // цена медовухи (x1)
    tinctPrice: number     // цена настоек (x2)

    rarePremium: boolean   // премия редким сортам (x4)
    honeyPrice: number     // цена мёда (x6)
    agingQuality: number   // качество выдержки (bk1-bk3)
    agedPrice: number      // цена выдержанного (bk4)
    badEventResist: number // снижение шанса плохих событий (soc1)
    provisionDiscount: number // скидка на материалы (soc2)
    goodEventBoost: number // усиление хороших событий (soc3)
    contract: boolean      // еженедельный контракт (soc4)
    handsZone: number      // зона мини-игры (hnd1)
    perfectReward: number  // множитель идеального отсечения (hnd3)
    perfectDay: number     // бонус к выходу после идеала (hnd4)
    unlockBarrel: boolean  // бочки видны в магазине (bk1)

    x2: { tinctPrice: 0.15 }
    x3: { brewSpeed: 1 }
    x4: { rarePremium: true }     (применяется вручную в bonuses())
    x5: { fruit: 1, veg: 1 }
    x6: { honeyPrice: 0.15 }
    bk1: { agingQuality: 0.05 }
    bk2: { agingQuality: 0.10 }
    bk3: { agingQuality: 0.25 }
    bk4: { agedPrice: 0.40, aroma: 0.10 }
    soc1: { badEventResist: 0.25 }
    soc2: { provisionDiscount: 0.20 }
    soc3: { goodEventBoost: 0.30 }
    soc4: { contract: true }      (применяется вручную)
    hnd1: { handsZone: 0.15 }
    hnd2: {}                       (UI-эффект, проверка skills.includes('hnd2'))
    hnd3: { perfectReward: 1.5 }
    hnd4: { perfectDay: 0.05 }

Механики, которые нужно будет внедрить в стор/компоненты (отдельными патчами):
    - brewSpeed: при тике партии daysLeft -= 1 + brewSpeed (или старт сразу
      со скидкой дней, чтобы не уходить в минус).
    - rarePremium: при продаже товара из «редкой» категории цена ×1,5,
      флаг купленного на этой неделе.
    - contract: еженедельный оффер в списке событий (фикс-цена ×1,3).
    - handsZone / perfectReward / perfectDay: параметры HeadsCutGame.
    - provisionDiscount: в магазине материалов цена ×(1 - скидка).
    - hidden: в SkillTree узел рисуется призрачно (opacity 0.25, без клика),
      условие раскрытия проверяется через useGame.
    - respec («Книга Тыка»): см. п. 8а ниже.

Три оси выбора:
    Ось 1 (характер vs чистота):   d3  ↔  r3
    Ось 2 (терруар vs характер):  o3  ↔  d3
    Ось 3 (дух vs абсолют):       bk4 ↔  r4

Легальные «большие» билды:
    - «Душа и тело»: d3 + bk4 + o3 (ароматный билд, максимум характера,

    - «Завод»: r3 + r4 (чистый спирт, отказ от души и бочки).

    - «Руки»: hnd4 + d3 (мини-игра как основной источник дохода).

Нелегальные: всё сразу. Именно этого мы и добивались.

10. ПОРЯДОК ВНЕДРЕНИЯ И РИСКИ
================================================================================

Порядок (каждый шаг — рабочая игра):
    Шаг 1. Правки цен (cost) и requires — только массивы, ноль новых механик.
    Шаг 2. Кросс-узлы x1-x6 + ветка oak (эффекты уже ложатся в существующие
           multiplier-пайплайны цены).
    Шаг 3. Ветка hands + параметры в HeadsCutGame.
    Шаг 4. Ветка social + события (худший объём работы — события, потому что
           нужно состояние «шанс/множитель» в генераторе событий).
    Шаг 5. Квесты веток, скрытые узлы, книга Тыка.

Риски:
    - Очков в игре должно хватать на ~50-60% дерева за «толстый» прохождение.
      Если очков мало — цены 4/6 сделают позднее дерево мёртвым. Проверить
      средний доход очков за партию на статах.
    - soc4 (контракт) может сломать рынок: гарантированная цена ×1,3 без
      риска — слишком сильно. Возможный предохранитель: контракт только
      на 1 партию и не чаще раза в неделю.
    - bk4 конфликт с r4 требует, чтобы UI явно показывал конфликты до
      покупки (иначе игрок будет жаловаться). Проверка в canLearn уже есть —
      нужно отразить в визуале: замок с надписью «Конфликт с …».
    - Скрытые узлы с отрицательными координатами (hnd3/hnd4) — после
      согласования сдвинуть, чтобы канвас не расширялся вверх.
